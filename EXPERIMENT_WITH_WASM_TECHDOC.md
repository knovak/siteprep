# Standalone WASM applications

`initiatives/experiment-with-wasm/work/` contains a local fork of Bookmark Sorter from commit `48c0f4b54a89480949ee86ffd04b3b67dcbb5dbf` (full SHA in `fork-provenance.json`). It is an initiative capability/output under development, not a reference dependency of any published deck or demo. Neither original app nor its hosting settings is changed.

## Source and execution

- `src/pile-page.mjs` retains the original card UI and its controls. Local calls replace network requests; export builds a downloadable Blob. Local tools expose full backup, restore, sample bookmarks and sitting/template controls. Cards accept locally chosen raster images.
- `src/bookmark-store.mjs` forks the D1 store's prepared SQL with local ownership. `selection-sql.mjs` compiles normalized boolean expressions into bound SQL. The store retains deduplication, stable indexed paging, tags/verdicts and history.
- `src/local-app.mjs` forks the route contracts into an in-process dispatcher. Request/Response are message envelopes with a synthetic origin; there is no HTTP listener or fetch transport. Identity, remote capture and cloud account routes are removed.
- `src/sqlite-adapter.mjs` implements prepared `bind`, `all`, `first`, `run` and atomic `batch` operations using actual SQLite/WASM. Statements are freed in finally blocks. Snapshot export restores the `foreign_keys` connection pragma that sql.js resets when reopening the database.
- `src/runtime.mjs` serializes requests. Every mutating action snapshots previous state, runs with a savepoint, commits, and awaits durable storage before reporting success. Dispatcher errors roll back the savepoint. Failed persistence restores the previous in-memory database. State never silently falls back to a JavaScript memory store.
- `src/persistence.mjs` writes the SQLite byte array into experiment-specific IndexedDB. A read/write transaction compares the expected revision before writing, preventing stale tabs from overwriting another tab. The initial database starts empty and schema version is explicit.
- `src/browser.mjs` instantiates the embedded WASM bytes, wires local persistence/backup/restore and pictures, and reports startup/save errors in the UI. SQL and the browser IndexedDB APIs require no service worker, OPFS, cross-origin-isolation headers, or network access.

DOM rendering, HTML/JSON parsing, Unicode normalization, expression compilation, proposal grouping and storage plumbing remain JavaScript. SQLite's native engine inside WASM performs the database work. This boundary is deliberate and is described to the user.

## Database and import boundaries

`schema.sql` is the ordered original SQL migration sequence with user allowlist migrations omitted and schema version 1. No real identities or bookmark data are copied. The full database format carries an application ID, `BSW1`. Restore checks that ID, version, the exact table/index schema (rejecting added triggers/views), SQLite integrity/foreign keys, valid absolute bookmark URLs, and allowed inline raster images before replacing state. A failed restore leaves the current database intact.

Original bookmark JSON import/export keeps the `bookmark-sorter/v1` contract. A subset import does not remove absent records; URL matches merge tags and preserve existing verdicts. Images, saved selections and sitting history travel only in a full `.sqlite` backup. HTML/JSON imports retain all valid absolute URLs, including legacy `javascript:`, `data:`, `file:`, `mailto:`, `place:` and `about:` bookmarks, through export, reload and full backup/restore. These addresses are stored as data: the card renderer's `externalUrl()` permits only HTTP(S) links, and other titles/notes render through `textContent`. Copy URL remains available for every bookmark. Malformed or relative URLs still fail the file atomically. Images are restricted to PNG/JPEG/WebP, decoded before storage and capped at 5 MB. Full databases are capped at 100 MB. The HTML's CSP permits HTTP(S) data/image downloads but denies frames, objects and external scripts; it permits the embedded WASM and inline UI. Following an explicit HTTP(S) bookmark link opens its website separately.

Snapshot persistence is designed for modest personal collections. Every action copies the entire database, including pictures, so memory and save cost increase with database size. Browser storage can be evicted and varies for file origins; explicit full backups are essential for transfer and recovery. Chromium covers the complete direct-file suite. The new online journeys also pass Playwright Firefox and WebKit; physical Safari/iPad acceptance remains separate.

## Build and tests

The initiative package pins sql.js and esbuild in its own lockfile. `npm ci` at the root supplies the repository's pinned Playwright; `npm ci` in `work/` installs its build/runtime packages. `npm run build` there uses `scripts/build.mjs` to bundle source, CSS, schema and the WASM bytes into `dist/index.html`, alongside the sql.js license and a checksum manifest. The license is also embedded in the HTML for single-file redistribution. The distribution is intentionally committed so it can be opened without a compiler, package manager or server. SQLite is public domain; sql.js is MIT licensed.

`npm test` in `work/` runs actual WASM-backed integration tests and compares SQL selection membership to the original JavaScript evaluator. It covers deduplication/round trip, mutations/undo, reports, collections, backup/restore, invalid input, rollback, stale writers and a generated 5,600-item workload.

`npm run test:browser` opens the committed single file with network access disabled. It exercises visible import/paging/verdict/undo/select/tag/export controls, persistence across reload, local pictures, full backup/restore, phone behavior, conflicts between actual browser tabs and missing WASM/storage failures. A mixed legacy HTML fixture reproduces the former whole-file rejection and checks that every entry survives; its non-web titles create no links, execute no bookmarklet and open no extra page, including after reload and JSON reimport. Integration coverage also checks full backup/restore and malformed-URL rollback.

`.github/workflows/wasm-standalone.yml` installs the two lockfiles, rebuilds and checks the committed distribution for drift, then runs both suites. It is scoped to changes in this initiative, this technical document or that workflow. It does not deploy. The repository's normal build remains separately required. Screenshots are generated after that final build under `screenshots/` as described in BUILD_TECHDOC.md.

## Tide Here conversion

The second independent package is `initiatives/experiment-with-wasm/work/tide-here/`. It leaves Bookmark Sorter's existing path unchanged. `src/day-model.mjs`, `src/astronomy.mjs`, the SunCalc vendor module and base styles are forked from Tide Here, with import paths adjusted. `fork-provenance.json` records source hashes and the unchanged original server modules used as comparison evidence.

`src/guest.mjs` contains the original pinned `@neaps/tide-predictor` 0.11.0 call with Schureman corrections, normalizing centimetres to metres. The guest bundle is passed as text to `src/wasm-engine.mjs` and evaluated exclusively by QuickJS compiled to WASM (`quickjs-emscripten` 0.32.0). The VM has a 64 MB heap cap, 1 MB stack limit and interrupt deadline. Handles are disposed on success and error. The browser runs this in an embedded Blob worker; `src/worker.mjs` uses correlated requests and propagates engine failures. No host-side tide fallback exists. This preserves mature JavaScript inside a WASM interpreter; it is not a native numerical compilation or a speed claim.

`src/data.mjs` decodes the compact model, preserves the original 40 km coastal-selection rule including antimeridian distances, and searches a normalized offline GeoNames catalogue. `src/forecast.mjs` places events in five original coast-local rows, converts heights to metres and enriches them through the original SunCalc layer. `src/browser.mjs` renders the five-day UI, disambiguates places, accepts coordinates/geolocation and alternate model points, and provides downloads. Revision tokens prevent a slow earlier request from rendering over a newer selection. Browser Intl and SunCalc remain outside the WASM VM.

`src/history.mjs` stores the last 100 forecasts in a separate localStorage namespace. Failed browser storage affects history durability only and produces a visible message. JSON export/restore validates the format before merging; a 10 MB upload cap bounds the input. It contains no executable content, and imported strings render through textContent. History is separate from the read-only embedded dataset, which survives storage clearing or file copying. The harmonic model has no yearly expiry, but model accuracy, geography, time zones and browser support can change over time.

`scripts/pack-data.py` verifies every source package object against its checksum before combining 376 tiles into 65,203 records. All 34 constituent names/order, water flags, centimetre units and 40 km coverage are checked. The format is a little-endian uint32 JSON-header length, a UTF-8 metadata header, then fixed 292-byte records: float64 latitude/longitude, uint16 zone index, int16 interpolation quality, and 34 pairs of float32 amplitude/phase. The whole file is gzip-compressed. The source package and output hashes, provenance, transformation precision and source licences live in `data/manifest.json`. It also records the source hashes for the 170,946-place GeoNames snapshot and joined administrative labels. These are public/appropriately licensed geographic inputs, not personal location histories.

`scripts/build.mjs` verifies the committed data hashes, separately bundles the guest, worker and browser UI, and embeds both compressed datasets and all code into a single HTML file. Its CSP allows inline code, WASM and the Blob worker while permitting HTTP(S) data requests and denying external scripts. It has no application-server hosting configuration; the optional online controls use browser fetch. Build input data and the generated 39.5 MB HTML are committed, so another checkout can rebuild without access to the retained original atlas. `dist/build.json` records the exact artifact hash. Software licences and data attribution are embedded; the reviewed AVISO licence is retained alongside the derived source data.

`scripts/record-reference.mjs` is an explicit evidence-generation tool using the unchanged original server forecast implementation and full-precision coastal package. The normal tests consume recorded reference results rather than regenerating expectations. Five integration tests cover 12 forecast cases across continents and 2036, point/constituent counts, finite coverage, name search, DST/date-line/polar astronomy and history failure/restore. Five browser tests copy the single HTML to an unrelated directory, disable networking, exercise five regions and alternate points, future dates, invalid/inland requests, history loss/recovery, mobile layout, denied geolocation and missing worker startup. Numerical tolerance is implementation parity, not new scientific validation of FES2022.

The standalone CI workflow now also installs Tide Here's third lockfile, rebuilds its committed artifact, checks for distribution drift, and runs both Tide Here suites. The online journeys pass Chromium, Firefox and WebKit; earlier offline browser evidence is recorded in the initiative. The standalone edition defaults to online place lookup and official station predictions, with labelled FES2022 fallback and an explicit local-only mode. Each forecast identifies its source and datum; coverage limitations and no-navigation guidance remain visible in the interface and README.

## Static demo packaging and release

`work/scripts/build-demo.mjs` (`npm run build:demo` in `work/`) stages the complete static website in `work/site/`. Landing/findings shells and CSS live in `work/demo-src/`. The generator uses the repository's markdown renderer at build time for `wish.md` and `findings.md`, adds contents anchors and scrollable table containers, and fills measured artifact sizes into the landing page. Landing and findings pages need no JavaScript. Only allowlisted documents, app distributions, licences and provenance are copied; package dependencies and personal data are excluded.

`work/demo-src/applications.json` pins committed source snapshots and HTML hashes. The generator checks them and the app build manifests before copying unchanged HTML to `bookmark-sorter/index.html` and `tide-here/index.html`. Metadata is not regenerated from HEAD/path history during a build, since squash merges can change commit IDs without changing content. Updating an app requires recording a new committed snapshot. `provenance.json` carries source initiative names, relative artifact names, commits and original fork hashes as metadata, without paths back into the mutable initiative tree. This also satisfies the repository's published-output independence check.

The initiative declares a `demo` deployment sourced from `work/site` with destination `experiment-with-wasm`. `release-initiative` validates committed source and calls the atomic `deploy-demo` helper; the initiative release record comes from `initiatives.mjs deployments ... record --env prod`. Production becomes live after merge and Pages publication. The build also generates the separate test preview under `preview/initiatives/experiment-with-wasm/` from staged source.

`npm run test:demo` uses pinned Playwright and the loopback-only static verification server in `work/demo-test/server.mjs`. The server is a test tool, not an app backend or distributed dependency. Four browser checks compare release files with the staged package, verify the wish/links/anchors, follow both apps from the landing page and exercise samples after switching offline, and check mobile overflow. The default test directory is `demos/experiment-with-wasm/`; an absolute `WASM_DEMO_ROOT` selects the staging directory for pre-release checks. CI also triggers on this demo, rebuilds the package, checks drift and runs these cases against `work/site/` after the application tests. This lets a fix reach the branch preview without requiring a production release. Run the default release comparison when promoting the staged package.

The original direct-file app paths stay intact. Website findings explain the different storage origin and backup/restore for transfer. The static website does not yet register a service worker or guarantee Home Screen offline reopening. Desktop Chromium screenshots do not establish iPad acceptance.

## Internet retrieval (September 8, 2026)

`work/src/network.mjs` is bundled independently into both single files. It validates HTTP(S) URLs without embedded credentials, omits request credentials/referrers, bounds response bytes while streaming, and implements cancellation/timeouts. There is no public proxy or secret API key in the apps. The optional bounded cache keeps original retrieval timestamps, returns stale data only after a failed load and never treats cancellation as a cache fallback. Full or denied storage leaves a memory-only cache.

`work/src/online-bookmarks.mjs` parses metadata inside an inert template (never inserts downloaded markup), requests named Microlink modes, and downloads/decodes images into bounded PNGs. `runtime.savePreview` runs through the same serialized, atomic snapshot/persistence path as local changes. It checks collection membership, preserves user attached pictures, caps images/text, and leaves bookmark title/URL/note/verdict/tags untouched. `pile-page.mjs` wires URL import, picture URLs, a sequential 12-card preview batch, per-item failures and cancellation. Card picture controls share an overlay inside the image area so they cannot cover bookmark titles. HTTP 429 stops the batch. URL imports use the existing import dispatcher with the captured destination collection and 20 MB limit. The schema and full-backup format remain unchanged.

`work/tide-here/src/online.mjs` owns Photon searches, NOAA/CHS catalogue normalization, bounded nearest-station lists and UTC prediction normalization. The normal form, coordinates, geolocation, history and deep links all prefer online predictions. `automaticPlace` trusts Photon ranking and prefers a settlement over a leading boundary, matching the hosted geocoder policy. Other online matches remain in collapsed options; offline catalogue matches still require one exact label/prefix or sole result. Cache namespace v2 prevents old Photon entries without ranking metadata from restoring the former chooser behavior. `automaticStation` uses the hosted 25 km / 0.6 rule; ambiguous stations open a chooser. Failed search falls back to the catalogue, and failed/no-station tide lookup falls back to the local model with a visible reason. Local-only mode and `navigator.onLine === false` suppress normal online requests. Optional controls are grouped in a collapsed sources section. Time zones use a nearby existing coastal-model assignment, or UTC when none is available; the UI explains this. NOAA events retain provider H/L types; CHS extrema are sorted/deduplicated and require alternating heights before types are inferred. Five-day filtering uses the existing local-day model. Official forecasts override the engine/source/datum metadata so downloaded API predictions cannot be mistaken for WASM model output. Browser revision tokens and abort signals prevent earlier online requests from replacing a later selection. Provider failures leave the local model/current forecast intact.

The public services are Photon (OpenStreetMap data, reasonable-use demo service), NOAA CO-OPS, CHS IWLS and optional Microlink (unauthenticated free quota). Their URLs, attribution and conditions are in the UI/findings. Requests are initiated through explicit controls. Chromium live probes verified NOAA, Photon and Microlink; CHS API JSON was available to non-browser probes but CORS blocked Chromium at both file and HTTP origins. Deterministic CHS tests verify adapters and fallback behavior rather than claiming live availability.

Additional Node and Playwright tests run under the existing standalone workflow and cover transport bounds/credentials, cache timestamps/stale fallback, provider/datum correctness, partial station failure, URL import, inert metadata, image persistence, screenshot mode, quota/cancellation failures and phone layout. Existing offline and WASM parity suites are retained. Rebuild both apps, commit their snapshots, update `demo-src/applications.json` with those actual committed hashes, then package `work/site`; do not change `demos/` until production release is explicitly requested.

## Bureau tables and coast-local today

`work/tide-here/src/australia.mjs` reads the embedded official annual dataset. The build imports the original Australian annual-source validator and checksum-recorded `bom-annual-2026.source.json.gz`, normalizes all 76 ports / 103,597 extrema, and compares the complete result with the decompressed, committed `data/australia-bom-2026.json.gz`. It verifies that file against `data/manifest.json` and supplies the unchanged bytes through the isolated `tide:australia` build namespace. Recompressing on every build produced different HTML on macOS and Linux because their zlib versions differ. After reviewing an annual-source change, run `node scripts/build.mjs --refresh-australia` in the Tide Here package to regenerate the snapshot and its checksum explicitly. `dist/build.json` records the dataset version, counts and input/embedded SHA-256 values. The generated HTML contains everything it needs and has no runtime imports from another initiative or service.

Station lookup first checks the included Bureau catalogue within the existing 150 km bound; elsewhere NOAA and CHS retain their network paths. Bureau stations keep their official IANA zones and datums. Both online and offline automatic mode can select Bureau data; Local model only explicitly selects FES and suppresses requests. All five requested days must fit the annual coverage, otherwise the app explains the limitation and uses FES. Forecast exports retain the full source attribution, disclaimer, provenance and a separate `official.bundled` marker; the UI says “2026 tables”, links the station PDF, and offers no misleading live refresh for bundled tables.

The First day input and Today button are removed. Every entry point calculates five days starting today in the selected coast’s zone; old `date` fragments are ignored. Tests advance the browser clock to check future operation and the December year boundary. `test/australia.test.mjs` compares actual Bureau events and datums against the unchanged hosted provider at Mooloolaba, Sydney across DST, and Cocos, and rejects incomplete annual windows. Browser tests reproduce plain San Diego with California/Texas/county matches and Maroochydore online, offline and past annual coverage.

The `compare-tide-sources` app collector clears the former date control only when it exists, so the same comparison workflow supports both released and preview app versions.

Embedded gzip data streams directly from Uint8Array memory through DecompressionStream, avoiding WebKit’s Blob I/O failure after connectivity is disabled. The Bureau browser test clears saved data, reloads the file, disables connectivity and then loads its annual tables for the first time, so a warm dataset or saved response cannot mask that failure.
