Optional improvement menu — 2026-09-06

These are proposals, not a plan. Any one can be selected as a real todo item, redirected in review, or left here indefinitely. Closing the proposal pull request unmerged is also a complete answer.

CandidateWhy it could helpLikely sizeBoundary and evidence
Add a dedicated harvest skillHelp currently has to provide a reusable prompt and point an assistant at the low-level private protocol. A named skill could make a bounded repeat harvest discoverable and consistently preserve the store, identities, judgments, source checks, and deployment handoff.MediumRequire explicit sources and dates; use read-only Gmail operations; keep raw bodies in memory; keep all mailbox-specific files ignored and mode 0600; never replace the store, publish it, or deploy production. Exercise a re-harvest with overlap, a new issue, an attribution refusal, and a failed extraction before adopting it.
Make hosted-to-local judgment reconciliation one guided operationHosted judgments now survive refreshes in D1, but using them for tagging, offline review, or publishing still requires an export followed by a local import. A checked handoff could remove the easiest step to forget.SmallKeep an inspectable verdict file as the boundary; refuse the wrong store id, retain later-wins and idempotency rules, and never give the browser a direct write path to the story store. Demonstrate a duplicate import, a stale export, a cleared judgment, and recovery after an interrupted handoff.
Publish a curated kept-and-emphasized SiteThe provenance-safe generator already produces the shareable page promised by the original wish, but where that page is hosted remains deliberately unsettled. A separate curated Site would make selected stories readable without exposing the private review surface.MediumRequire an explicit publication and access decision; deploy private by default; include only kept and emphasised stories through the existing allow-list; exclude source-message provenance, Gmail searches, judgment controls, unjudged stories, and the private review database. Verify the generated bytes and access policy independently of the review Site.
Add saved compound filters for larger collectionsThe current single-tag filter works for a few hundred stories, while the stored tag and verdict conventions already align with the Bookmark Sorter selection model. Named combinations such as a theme plus unjudged status could make repeated review and publishing cuts easier.MediumDefine a small deterministic expression subset before adding UI; preserve free-string tags and the open verdict vocabulary; keep filters local to this one store; do not change story identity or import formats. Recheck pagination, clusters, page-scoped sweeps, exports, and phone layouts on the full collection.
Add a private harvest-health summaryExisting run records contain issues found, accepted stories, merges, count-band flags, overrides, and refusals, but the evidence is buried in private JSON and log notes. A compact owner-only view could make a missing or drifting source visible before the review pile quietly thins.SmallDerive only aggregate counts already recorded; show the requested date range and per-source coverage; include no message ids, Gmail searches, story text, or analytics. Treat a count-band change or single-HEAD follow as a separate recorded decision, never an automatic response to one unusual issue.

The strongest next increment is Add a dedicated harvest skill because the private protocol now works, the Site itself says that no dedicated loading skill exists, and every repeat load otherwise depends on reproducing a long, privacy-sensitive handoff correctly. The hosted-to-local judgment operation is the better choice if real use shows that exporting and importing judgments is the more frequent source of friction.
