Specification

Drafted October 21, 2026 (Australia/Brisbane), from the wish, reviewed objectives, decisions, and supplied reference. This specifies behavior and implementation evaluation; it contains no implementation or browser-performance results.

Experience

Photo markers is a static browser application for making square JPEG dividers. A single-image editor and a CSV batch view share the same design controls, timestamp rules, renderer and export checks. The browser performs the work locally using WASM for a substantive part of the actual export. Chrome and Safari on desktop and iOS are the supported families; exact versions and devices belong in the test record.

The first screen offers One marker and CSV batch, a visible preview, and a short local-processing explanation. Runtime preparation has a loading state, progress where available, failure details and Retry. Once the necessary static assets are loaded, editing, previewing, CSV import, generation and downloads work with the network disconnected. No account or processing service is needed.

One marker

  1. Enter an optional title, select Donut, Star or Solid color, and change the applicable colors. Advanced controls expose size, font and outline width.
  2. Enter date/time or leave them blank. See the effective timezone and the interpreted local time and offset beside the fields. Choose another timezone when needed.
  3. Inspect the preview and filename. Generate freezes the current settings and timestamp, produces and checks the JPEG, then offers Download JPEG. A separate generation action makes a new timestamp for a blank-date/time marker; downloading the same result again does not.
  4. Editing settings marks the old result as belonging to the previous settings. Keep it obtainable with that label until a new result succeeds or the user discards it; never relabel old bytes as a new export.

Empty titles are valid for every design, including a completely plain solid-color square. Titles are single-line in the first release; embedded line breaks receive an actionable validation error. Input and batch contents remain in the page session. Reloading may lose them, so explain that and offer an export of the current batch settings. Persistent projects and offline installation are deferred.

Appearance contract

The default is the inherited donut: 2000 × 2000 pixels, JPEG quality 95, black background, red ring, #b6d7a8 center, black bold title and white outline. Use opaque RGB colors; JPEG has no transparent background. Color pickers are paired with editable hex values and the legacy friendly-color names. Unknown values are errors rather than silently substituted colors.

DesignGeometry and controls
DonutCenter at (size/2, size/2). Outer radius is size/2, touching all four side midpoints. Inner radius is 78% of the outer radius. Background, ring and center colors map directly to the reference's corner, donut and center controls.
StarA filled regular five-point star, first outer vertex pointing up. Alternate five outer radii of size/2 and five inner radii of 0.45 × outer radius, in 36-degree steps around the image center. Background fills the square; shape color fills the star. No inner circle is drawn.
Solid colorBackground fills the whole square. Shape and center color controls are hidden and ignored for rendering. Title and outline controls remain available when text is present.

Store unused color values when switching designs, so switching back restores them. The inherited red ring value becomes Star's shape color; center color applies only to Donut. These are specification choices within the three reviewed designs, not additional shape families.

Retain a size control, initially bounded to integer sides of 256–4096 pixels, default 2000. The upper bound is a proposed supported limit to verify on iOS, not a measured capacity. Unsupported requests must be rejected before allocating image buffers. JPEG quality remains fixed at 95, as in the reference.

Bundle a licensed bold font and show its name. Permit choosing a locally supplied TTF/OTF font without uploading it; identify it by a session-local font key for batch reuse. Validate font loading, glyph coverage and text fit before export. Do not silently fall back to a different font or emit missing-glyph boxes. More bundled fonts can be added later after licensing and size review.

Center the title using measured glyph bounds. Preserve the reference's Donut text box: width 2 × inner radius × 0.78, height half that width. For Star, use a centered box of width 0.60 × size and height 0.25 × size; text may overlay the star's concave regions. Solid color uses width 0.78 × size and height 0.30 × size. Auto-size bold text from 4 pixels upward, including the outline in the fit calculation, and reject an unfit title rather than clipping it. Automatic outline thickness is max(1, floor(font size × 0.045)); an advanced integer override from 0–64 export pixels preserves the reference's programmatic option. Validate an override against the available text box.

Preview and output use the same resolved parameters, font metrics and geometry. The authoritative preview is a scaled rendering of the generated image; it must not be an independently laid-out approximation. A lower-resolution draft can respond during editing, labeled as a draft until the actual export preview arrives. Discard stale preview responses after later edits.

Dates, times and metadata

Use ISO Gregorian dates YYYY-MM-DD and 24-hour times HH:MM or HH:MM:SS, to whole-second precision. Seconds default to zero. Validate real calendar values without normalizing invalid dates. Initial supported years are 1900–2099; other dates receive a visible range error.

InputsInterpretation
Date and time both blankCapture the current instant once when Generate starts and show it in the effective zone. A batch uses one captured instant for all rows requesting now, including retries within that generation run.
Date present, time blankMidnight, 00:00:00, on that date in the effective zone.
Date and time presentThat wall-clock date/time in the effective zone.
Time present, date blankValidation error: enter a date or clear the time to request now.

The zone initially comes from the browser, with a visible UTC fallback if detection fails. Offer searchable IANA timezone names plus UTC, and show an example place label and the offset at the selected date. Never interpret a date-only string as UTC through a generic date parser. A zone is a rule set; its offset depends on the chosen date.

A nonexistent local time, including a skipped midnight, is an error with a request to choose another time. A repeated local time requires an explicit Earlier or Later occurrence showing the two offsets and resolved instants. Never silently choose an occurrence or shift a nonexistent time. A captured current instant is already unambiguous. The Temporal timezone documentation explains these distinctions; implementation may use a pinned local library or a compatible fallback rather than assume native Temporal support.

Write the resolved local timestamp as YYYY:MM:DD HH:MM:SS into all three required fields: DateTimeOriginal, DateTimeDigitized and IFD0 DateTime. Write matching OffsetTimeOriginal, OffsetTimeDigitized and OffsetTime as signed HH:MM offsets, plus a Software identifier. For example, Brisbane midnight on October 21, 2026 is 2026:10:21 00:00:00 with +10:00, representing 2026-10-20T14:00:00Z. Keep the IANA name, resolved instant, local timestamp and occurrence in the batch manifest; do not pretend the numeric EXIF offset stores an IANA zone.

Use an independent parser to read the final JPEG's date/time and offset fields before making it downloadable; missing or unequal required tags fail that item. The build/test toolchain also checks files with an independent image/metadata reader, separate from the export implementation. EXIF validation follows the timestamp/offset field relationships documented by ExifTool's tag reference. The reference generator's successful-JPEG-without-EXIF fallback must not carry over.

Optional location-to-zone inference is deferred from the first release. A bundled place list would add download size and incomplete coverage; coordinate-to-zone lookup would still need a place resolver or coordinate input. A remote geocoder would add a network dependency and disclose the search. Explicit timezone selection meets the requirement without those costs. Revisit local location assistance after the core export path works.

CSV batch contract

Import UTF-8 comma-separated CSV, accepting an optional BOM, CRLF/LF records, quoted commas and escaped quotes. Reject malformed quoting, duplicate headers, unknown headers and invalid nonblank values with a row/column error. Headers are the exact lower-case names below; show a downloadable template. At least one recognized header and one data record are required. No particular column is mandatory because untitled markers and shared defaults are valid.

ColumnsValues and defaults
titleOptional text; blank means no title. It does not inherit the single editor's title.
date, timeOptional; omitted/blank values follow the timestamp table above. They never inherit an unrelated date/time left in the single editor.
timezoneIANA name or UTC; omitted/blank inherits the displayed batch zone.
occurrenceearlier or later; blank is accepted for an unambiguous time. A repeated local time requires a row choice before generation. An occurrence supplied for an unambiguous time is harmless and shown as unused.
shapedonut, star or solid; omitted/blank inherits the batch style.
background_color, shape_color, center_color, text_color, outline_colorOpaque hex or a supported legacy friendly name; omitted/blank inherits the corresponding batch setting. Validate supplied colors even when a design does not use them, and mark unused controls in the row detail.
sizeInteger side length in pixels within the supported range; omitted/blank inherits the batch setting.
fontBundled font key or a font already loaded in this session; omitted/blank inherits the batch font. No URL or filesystem path is fetched.
outline_widthauto or integer 0–64; omitted/blank inherits the batch value.
filenameOptional preferred stem. Derive from the title or marker when blank; always append a stable row suffix.

A physical empty line outside quoted records is ignored and counted in the import report. A valid data record of blank cells is a real marker using defaults; retain it. Whitespace-only optional values count as blank, while interior title spaces are preserved.

The batch view shows source record number, title, effective style, effective time/zone, validation status and a selectable preview. Shared batch settings supply defaults; nonblank CSV values override them; explicit row edits override both. Clearing a row override restores inheritance and is labeled accordingly. Revalidate affected rows when shared settings change. Keep imported data and successful files when another row fails.

Before generation, display the fully resolved values and errors. Block generation until invalid rows are corrected or explicitly excluded; show excluded rows and counts in the report. Freeze a generation snapshot so later edits cannot change a job midway. Each row progresses through queued, generating, verified, failed or cancelled. Progress names the current row and totals. Cancel stops pending rows, preserves completed files and releases the active renderer when safe; a hung worker may be terminated and restarted. Retrying a failed row uses its frozen parameters and resolved timestamp.

Downloads and resource bounds

A single marker downloads as one .jpg. A batch primarily downloads as ZIP containing unchanged verified JPEG bytes and manifest.json with row identity, filename, effective settings/time, status and errors. Do not recompress JPEGs through another image encoder when packaging. Also offer individual verified files, so a ZIP or browser download problem does not make them inaccessible. Each ZIP part requires a deliberate download action; do not fire a burst of automatic downloads.

Filenames use a safe stem, a date/time component and a stable four-digit record suffix, for example baltics-20261021-000000-0003.jpg. Strip path separators/control characters, normalize reserved names and cap the stem at 80 characters. Show the actual names before generation. Repeated titles, timestamps and requested stems must still produce distinct names within a run, without changing row order. The JPEG's EXIF timestamps, not its ZIP entry time or filesystem modification time, carry the intended photo time.

Proposed first-release bounds are 100 data rows per imported batch, a 1 MiB CSV, and downloadable ZIP parts containing at most 25 MiB of JPEG payload each. Hold at most one full-resolution render at a time, release intermediate buffers, and avoid retaining full-resolution previews for every row. At 2000 pixels an RGBA image alone is about 16 MB; at 4096 it is about 67 MB, before additional encoder/runtime copies. Limits are preflight constraints to test, not a claim about device memory.

Flush completed parts into obtainable downloads and require the user to save or discard them before retaining enough new results to exceed a 50 MiB compressed-output budget. A single file above the ZIP-part target is offered separately. An allocation/worker/package failure identifies its stage and affected row; it must not erase the imported batch or falsely report success. Reduce the supported limit with a documented test result if physical iOS cannot meet it; do not advertise an untested larger limit.

Implementation options and discovery gate

The first implementation task is a small comparison using real JPEG exports, not a library vote from the user. These are candidates, not selected dependencies or proven performance:

ApproachStrengthsCosts and evidence needed
Pyodide worker with Pillow and a pinned metadata writerReuses the supplied drawing/font logic. Pyodide lists Pillow among its packages and documents worker execution. Image generation runs through its WASM runtime.Measure total runtime/package/font transfer and cold start, iOS memory, font/glyph handling and mandatory EXIF-offset writing. The reference needs browser adaptation and failure handling.
Browser drawing/font APIs plus a WASM JPEG encoder and metadata writerUses familiar browser controls and text rendering; the exported JPEG encoding supplies substantive WASM processing. Squoosh documents separately built JS/WASM codec modules.Establish a maintained, licensed build path, reproducible codec parameters, exact preview matching, explicit EXIF insertion and independent read-back. Canvas-only JPEG export would not satisfy the WASM requirement.
A purpose-built Rust/C++ WASM renderer/encoderCan centralize rendering, encoding and resource ownership in a focused module.Greater integration/build burden and text shaping, font and metadata work. Worth considering only if measured results justify it. No suitability claim is made without a prototype.

Primary documentation consulted October 21, 2026: Pyodide worker guide, Pyodide packages, and Squoosh codec build instructions. These establish available mechanisms, not compatibility of an unbuilt application.

Compare at least the first two viable routes on the default donut with title, a blank solid marker, and a ten-row timed batch. Record exact dependencies/commits and licenses, transferred bytes, cold initialization, warm export time, peak-memory observations or their measurement limits, exported tags, browser results and offline behavior. Prefer the smallest maintainable approach that meets the contract; do not keep a second runtime just for comparison after selection.

The export path is: validate and resolve settings/time, draw with loaded fonts, encode through the selected WASM path, write metadata, independently read back, then expose verified bytes for preview/download. A worker owns serial generation and reports status; the UI owns editable settings and row status. Use ordinary transferable buffers and a single-thread baseline, without requiring cross-origin isolation headers or SharedArrayBuffer. Worker recovery must not lose the UI's job snapshot.

Pin and vendor all runtime assets, fonts, timezone support and licenses into the eventual static output. Initial static downloads are permitted, but generation must not fetch packages, fonts, remote images or a geocoding service on demand. Use relative URLs that work under the intended demo subdirectory. The application must have no runtime reference into initiatives/ after graduation.

Acceptance targets and next lifecycle step

These are targets for the later plan and test plan, not passed checks. Preserve the seven objective groups and verify all three designs, title-fit failures, a ten-row mixed CSV, date-only/now/time-only cases, repeated/skipped times, a different browser zone, ZIP extraction and exact JPEG-byte preservation. Include duplicate filenames, malformed CSV, worker/package failures, cancellation/retry, offline operation and loading from the deployed subdirectory. Verify actual exported image dimensions and all six timestamp/offset fields independently. Photo-library application testing remains outside this release.

Initial performance targets at 2000 pixels are an updated draft preview within 500 ms after runtime initialization; one verified warm export within 2 seconds on desktop and 5 seconds on physical iOS; and ten mixed markers plus packaging within 30 seconds on desktop and 60 seconds on physical iOS. Record cold-start transfer/time separately. UI status and Cancel must remain operable during generation; do not hide missed targets behind an unresponsive page. The comparison records measurements and explains any target revision before the implementation proceeds.

Test current stable Chrome and Safari on desktop, and Safari plus Chrome on a physical iOS device, recording OS/browser/device and browser engine where known. Emulation supplements rather than substitutes for the physical iOS download/memory check. Check keyboard access, visible labels/focus, row-error navigation, responsive layout and useful progress announcements. No physical-device success is presumed from desktop browser automation.
