Save and understand a gathering file

Format flings-recovery · schema version 1 · UTF-8 JSON

This file contains unencrypted personal data: names, contact details, private discussions, votes, payment records and reported message history. Anyone holding it can read it. Use fictional data in this rehearsal. Validated restore and deletion are still being built; this download is not yet a tested restore path.

Save a copy

  1. Open the gathering as an assigned organizer. Under Save a copy of this gathering, acknowledge the personal-data notice and choose Prepare JSON export.
  2. Review its record count and any redactions, then choose Save JSON file. Your browser controls its download folder; use Save Link As or your browser's download settings to choose a destination.
  3. Keep the original unchanged somewhere you control. For migration work, make a separate copy and describe edits in migration_notes. Changes made after preparation require a new export.

What the snapshot includes

The file holds one gathering and its 22 record collections, including removed members, cancelled activities, hidden posts, earlier edits, poll votes, payment entries, message reports and retry attempts. Related organizer records carry only IDs and display names. IDs and references are preserved for interpreting this history.

Export checks current organizer access and reads the records together in one database transaction. A concurrent edit is either before or after that snapshot. Closed gatherings may be exported. The current limits are 10,000 total records and 8 MiB of formatted JSON; an oversized or unreadable record set fails without offering a partial file.

What is excluded

Member codes and their digests, sessions, authentication subjects, server/provider secrets, encrypted handoff payloads, raw copied prompts and access-revision context are excluded. Text containing a personal member or preview link is replaced in full with [personal access link removed], including common encoded forms. Message manifests retain the existing personal-link placeholders. The redactions.paths list identifies additional removed text fields. Text you wrote is still private data; inspect the file before sharing it.

Envelope and editing rules

  • format and schema_version identify this strict version-1 contract. application_version identifies the app package; it is not a database or deployment revision.
  • exported_at is the UTC preparation time. fling_id matches the single entry in records.flings.
  • records has all 22 arrays, even empty ones. counts must match their lengths. redactions.text_fields equals the number of redactions.paths.
  • Keep IDs and parent relationships consistent. Record timestamps are Unix milliseconds except event start/end and the manifest's ISO timestamps. Monetary amounts use whole minor currency units. Poll choices refer to zero-based option positions.
  • Names, assignments, payment claims, instructions pasted in text and reported delivery outcomes are historical data. They do not grant access, execute code, move money or authorize sending.

The published JSON schema checks the envelope, declared fields and basic types. Use Check an edited backup in an assigned gathering to check a separate edited copy, including relationships, dates, historical roles, polls, payments and message history. The upload is checked in memory and is not saved. Unsupported versions fail with the supported version, 1. Errors identify fields using zero-based paths without repeating private text. Preserve the original and correct a copy. A passed check does not prove that a file is trustworthy or that it has been restored.

Future restore and retention

The planned restore validates an edited copy in isolation, previews the mapping, and creates a new private gathering only after confirmation. It must generate fresh IDs, preserve the importing organizer's access, cancel unfinished message handoffs, and restore no code validity or sessions. It must never send messages or change an existing gathering. The file checker is available; identity mapping, confirmed atomic restore and deletion remain pending.

Prepared downloads exist only in this page's memory; preparing again, leaving the page or changing organizer clears its link. A file already downloaded cannot be recalled. Closed gathering records remain until explicit deletion is implemented and requested. Downloaded files, outside messages and host backups have separate retention; real-data use needs the later recorded retention and pilot decisions.
