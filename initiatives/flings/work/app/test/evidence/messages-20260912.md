# Exact message review and prompt export — September 12, 2026 (UTC)

This second Phase 4 increment implements local exact-message review, approval
and copyable sending prompts. `build-message-handoff` remains actionable for
optional discussion posting, imported result preview/reporting and explicit
selected retries after account-history inspection. It does not complete T8–T10.

## Evidence

- `npm test`: 70 real-D1/domain/HTTP/time tests pass, including 15 new message
  tests. Each test database applies all six migrations; no database mock is used.
- `node test/messages-browser.mjs`: six journeys across Chromium, Firefox and
  WebKit at desktop and phone sizes. The receipt is
  `messages-browser-20260912.json`.
- The six audience and six coordination regression journeys have separate
  `messages-audience-regression-20260912.json` and
  `messages-coordination-regression-20260912.json` receipts. Prior receipts stay
  unchanged. Earlier gathering/assignment/access browser counts are not new runs.
- TypeScript, lint and the application build pass. Repository build and scope
  results are reported in the PR. `messages-source-20260912.json` records source
  hashes; no test receipt contains contacts, member links or cookies.

The new cases verify quoted/multiline/instruction-like data, exact whitespace,
correct per-membership links shared across both channels, incomplete-profile
omissions, explicit shared-contact review, stable IDs and repeated export,
one-to-five delivery bounds, trusted origin, rejected pasted bearer links,
redacted persistent history and encrypted recoverable payloads. Copying produces
only `exported for sending`, with unknown outcomes.

Time and race cases cover the earliest 14-day sending boundary, renewed review
with a new code, revocation cleanup, profile/addition/invitation/role changes,
closure/reopening, competing approval and another organizer's export attempt.
Injected changes after verification demonstrate that the final transaction
still rejects a changed profile, removed organizer or expired poll. Failed
preparation leaves no batch/delivery/review-audit records; separately issued
member codes retain their normal audit and expiry. Tampered ciphertext and
mismatched revision/fingerprint cannot export.

Browser checks exercise the actual form, keyboard review, both approval
checkboxes, repeated copy, redacted history and recopy after reload, stale-profile
rejection and removal of the old prompt. They found and fixed an error path:
the parent workspace cleared a stale child view without retaining its error;
the parent now displays the reason. Each journey checks overflow and page errors.
The clipboard API is stubbed; no test changes the user's clipboard, opens a
member link externally or operates Gmail/Messages.

## Remaining acceptance

T8 has audience, approval, link-window and exact-manifest evidence; reporting
and selected-retry behavior remain open. T9's optional linked discussion post
and atomic post/message/delivery creation remain unimplemented. T10 still needs
simulated imported-result validation and interrupted/unknown outcome handling,
then the independent authorized pilot on actual sender accounts. The prompt
instructs account verification and stopping on uncertainty; those instructions
are not evidence of external-tool reliability.

This increment is fictional local work with no registered deployment target.
Hosted identity, dependency remediation (the pinned install still reports six
moderate and eight high advisories), editable recovery, production release and
human pilot acceptance retain the existing later-phase prerequisites.
