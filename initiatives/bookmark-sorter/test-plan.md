# Test plan

How we know it works. `plan.md` ends every phase at a section of this document,
so "phase complete" is something that passes rather than something somebody
decides.

Numbered references to **O1–O8** are the objectives; **§n** is a section of
`spec.md` unless it says `plan.md`.

## 1. What testing is for here

`objectives.md` measures this initiative by **how much of the pile gets
resolved**, not by how well it is organised. That gives the test plan an unusual
top-level rule: *a test earns its place by protecting a verdict, or by protecting
the speed at which verdicts are made.* A test that pins a detail no objective
depends on is decoration, and this document deliberately has fewer of those than
a coverage target would produce.

It also means two things that are not usually tests are treated as tests here:
**a measured triage rate** (§12's instrument, first taken in phase 2) and **a
real pile going in and coming back out intact** (O1 and O7). Both are in §4 with
pass conditions, alongside the ordinary kind.

## 2. Layers, and what goes in each

| Layer | What it covers | Why there |
|---|---|---|
| **Unit** | The pure functions: `url_key` normalisation, the Netscape parser, the merge rules, the §8 expression evaluator, the gap rules of §6 | All are total functions of their input, all are where a silent wrong answer is possible, and none needs a browser |
| **Integration** | Import → store → grid; capture pipeline against a fixture web server; export → import round trip | The seams where a rule stated in one place is enforced in another |
| **Browser-driven** | The grid at three layouts, keyboard and pointer triage, `undo`, mark-then-sweep, the collection menu | O3 and O4 are claims about a screen, so they cannot be checked below one |
| **Measured** | Triage rate per session, capture coverage, duplicate-image distribution, backlog count | Numbers that decide things (`plan.md` §4) rather than numbers that pass or fail |
| **Manual, once per phase** | A sitting with a real pile | The failure this whole initiative is about — "organised but never read" — is not detectable by any automated test |

**No mocked third parties on the capture path.** Pass 1 is tested against a local
fixture server serving pages with, without, and with malformed `og:image`, plus a
404, a timeout, a TLS error and a parked domain. A mock returning what we expect
would pass while the real parser failed on the messy HTML that is the whole
difficulty.

## 3. Fixtures

Committed under this initiative, small enough to read and diff:

- **`export-small.html`** — a Netscape bookmark export covering the cases that
  break parsers: nested folders, a folder with no items, an item with no
  `ADD_DATE`, a `<DD>` description, unicode in titles and paths, an entry with a
  `javascript:` URL, and two entries whose URLs differ only by `utm_*`.
- **`export-overlap.html`** — a second export sharing roughly half its items with
  the first, for the merge rules.
- **`export-large.html`** — generated, 10,000 items, for the grid and the
  ingestion path. Generated by a committed script rather than committed itself.
- **`proposals.json`** — a §8.2 proposals file, including one URL that is not in
  the collection and one proposed tag that already exists on some of its items.
- **`export-v1.json`** — a hand-written `bookmark-sorter/v1` document, so import
  is tested against a file the code did not write.

## 4. Phase exit tests

Each section is the gate for the matching phase in `plan.md` §3.

### 4.0 — Host spike

Not software, so the exit is evidence rather than a passing suite: **every row of
§10's table filled in with what was actually observed**, and a `decisions.md`
entry naming the surface.

Two rows have pass conditions sharp enough to write down, because they are the
ones that decide the project rather than a feature:

- **Bulk data export** — a collection's worth of rows can be got out of the host
  in a form another program can read, by an ordinary user, without an account
  the project does not have. Anything less fails O7 outright.
- **A server-side secret store with a server-side place to call from** — a value
  can be held that the browser cannot read, and an outbound call can be made from
  a place that can read it. Failing this switches pass 2 off and nothing else.

### 4.1 — The pile lands

| Test | Pass condition | Protects |
|---|---|---|
| Parse `export-small.html` | Every item's title, URL, `add_date`, folder path and `<DD>` text survives; nothing is dropped and nothing is invented | O1 |
| Ingestion tags | Every item carries `src:`, `in:` and its `folder:` tag; the folder path matches the file's nesting | O1, §4 |
| `url_key` normalisation | The two `utm_*` twins collapse to one item; a case-different host and a stripped default port collapse; a differing query string does **not** | §4 |
| Original URL kept | The stored `url` is what was in the file, not the normalised form | §4 |
| Re-import the same file | Item count unchanged; no duplicates | O1 |
| Import `export-overlap.html` | Tags union; earliest `add_date` wins; no existing verdict or `note` is overwritten | §4, §5.1 |
| Import `export-large.html` | 10,000 items land, and the count is right | Sizing (§1) |

### 4.2 — The grid, blind

| Test | Pass condition | Protects |
|---|---|---|
| Virtualisation | With 10,000 items loaded, the DOM holds a screenful plus buffer, not the pile | §7 |
| Three layouts | 8×2 on a wide viewport, 4×3 or 3×3 on a tablet, one-at-a-time carousel on a phone | O3 |
| Verdicts | Each of the four lands on the focused item and on the marked set | O2 |
| `undo` | Reverses the last function as one action, including a verdict applied to a set | §7 |
| Backlog count | Untriaged count for the collection is correct after every action | O2 |
| No page load per action | No navigation and no full re-render on a verdict | §12 |
| **Measured: the blind baseline** | A sitting on several hundred real items records items judged and elapsed time; the rate is written into `spec.md` §12 as the first baseline | O3, §12 |

The baseline is a recorded number, not a threshold — there is nothing yet to
compare it against, which is exactly why `objectives.md` declined to set a target
before it existed.

### 4.3 — Captures, pass 1

| Test | Pass condition | Protects |
|---|---|---|
| Metadata ladder | `og:image` wins; `twitter:image` when it is absent; neither leaves the item imageless and says so | §6 |
| Anonymity | No cookie is sent and no session is used on any capture request | §3 |
| No JavaScript | A JS-rendered fixture page yields no image from pass 1 and is queued for pass 2 rather than half-parsed | §3 |
| Derivative only | The stored image is the downscaled one, at the fixed capture size | §3 |
| No re-fetch on view | Displaying an item makes no outbound request | §3, §12 |
| Failures as data | The 404, timeout, TLS and parked-domain fixtures each write the matching `err:` tag on every item sharing that `url_key` | §6 |
| Duplicate rule | Where one image hash covers items above the threshold, all of them are treated as imageless and queued | §6 |
| Pass 2 against the stub | The queue, gap rules, storage and switch all work with the vendor call stubbed; turning the switch on changes configuration only | §6 |
| **The key never reaches the browser** | A test over the built client bundle finds no vendor key and no vendor endpoint | §6 |
| **Measured: coverage** | What fraction of a real pile got a distinguishable picture from metadata alone | `plan.md` §3 |
| **Measured: duplicate distribution** | The real distribution of items per image hash, and the threshold chosen from it, recorded in `decisions.md` | §6 |

### 4.4 — Selections

The evaluator gets a table-driven test — one expression, one expected item set —
covering `and`, `or`, `not`, parentheses, precedence, a bare tag, a trailing `*`,
an unknown tag (empty set, not an error), and a malformed expression (a clear
error, not an empty set, since the two are indistinguishable to a user about to
sweep a verdict across the result).

| Test | Pass condition | Protects |
|---|---|---|
| Scope wrapping | Every selection made through the UI is wrapped `collection:<current> and ( … )`; no user-typed expression can reach another collection's items | §8.1, O8 |
| One evaluator | The administrative unwrapped path and the UI path are the same function with a different argument | §8.1 |
| `tag-apply` on a selection | Applies to every member; tags union rather than replace | O6 |
| Confirmation threshold | A verdict across more than the threshold asks first | §8.3 |
| Mark then sweep | `verdict-rest` applies to the selection minus the marked set; the inverted form (mark the keepers, sweep the rest) behaves identically | §7.1 |
| **`undo` reverses a sweep as one action** | Fifty items swept and one undo restores all fifty | §7.1 |
| Saved selection | Round-trips through storage and re-evaluates to the same set | §5 |

### 4.5 — The round trip

The test O7 actually makes, in three parts:

1. **Export → import into the same collection is a no-op.** Same items, same
   tags, same verdicts, same notes, no duplicates, nothing changed.
2. **Export of a selection is self-describing.** The file records the expression,
   carries exactly the selected items, and carries no captures.
3. **Export → import into a *different* collection** (§9.1) brings items, tags
   and verdicts across; the source is unchanged; the destination's items show
   their pictures immediately from the URL-keyed cache without a new capture.

Plus: importing `export-v1.json`, a file the code did not write, works; and an
import never overwrites an existing verdict or `note` — a rule stated in §4,
§5.1 and §9, and therefore worth one test per surface rather than one in total.

### 4.6 — Identity and collections

The central case needs two users, so it is a browser-driven test with two
sessions:

| Test | Pass condition | Protects |
|---|---|---|
| **Isolation** | User B cannot see, select, export or reach by any URL a single item of user A's personal collection | O8, §10 |
| Template listing | Every signed-in user can list `demo-template` collections, and no other kind across owners | §10.1 |
| Take a copy | Produces a private `demo-copy` owned by the taker, with `template_id` and `copied_at` recorded | §10.1 |
| Template is read-only | A user without `can_edit_templates` cannot write to a template by any path | §10.1 |
| Edit the template | Does not disturb an existing copy | §10.1 |
| Fresh copy | A second copy is made rather than the first repaired; the name may differ | §10.1 |
| Delete a copy | Removes the collection and its items; captures survive, being URL-keyed and shared | §5, §10.1 |
| Nothing joins through the user | A schema check: no path from an item to a user except through its collection | §5 |

### 4.7 — Turning pass 2 on

One contract test against the real vendor: a known URL returns an image of the
expected size, the call is made server-side, and the key is absent from the
client bundle. Then a bounded live run over gap items, with spend recorded.

## 5. The tests that exist to stop a decision drifting

Most of the table rows above check that something works. These check that
something stayed *true* — each one pins a decision that would otherwise be
undone by an ordinary, reasonable change, and each names the change it is
guarding against.

| Pinned | The drift it prevents |
|---|---|
| No cookies, no session on any capture request | Someone "fixes" coverage on login-walled pages by authenticating the fetcher |
| No key or vendor endpoint in the client bundle | Pass 2 gets turned on the quick way |
| Displaying an item makes no outbound request | A lazy re-capture on view creeps in and the grid starts waiting on the network |
| Every UI selection is collection-wrapped by the app | A "search all my stuff" feature makes the wrapping optional |
| An import never overwrites a verdict or a `note` | A "sync" or "newest wins" import is added and silently edits the user's own writing |
| Export carries no captures | Someone makes the file self-contained and it stops being movable |
| `undo` reverses a set operation as one action | A refactor makes undo per-item and nobody risks a sweep again |
| A tag is a free string with nothing marking its origin | A controlled vocabulary or a `source` column is added and §8.2's skills become a schema change |
| Nothing joins through the user to reach an item | Sharing becomes a retrofit rather than an addition |

## 6. What is not tested, and why

- **The vendor's rendering quality.** Not ours, not stable, and §3 already
  accounts for the failure mode by preferring a visible hole to a confident wrong
  picture.
- **Real websites.** The capture tests run against a fixture server; a suite that
  fetches the live web fails for reasons that have nothing to do with the change
  under test.
- **The rate target.** There is no threshold to fail against until phase 2
  produces a baseline. Until then the rate is recorded, not asserted.
- **Anything held out of the first version** — tab harvesting, pushing subsets
  into a browser, general sharing. The one thing tested on their behalf is the
  export format, which is what §11 says makes them cheap later.
